# p=7 CUDA-core `FUSED` gap study

GB200 1 GPU、`make CUDA=1 GPUFLAGS=-gpu=cc100`（nvcc `-arch=sm_100`）、
`namelists/perf_p7_fused.conf`（`Ne=32³`、`nstep=20`、graph off）。
親 commit `9dfea48`。対象は `CUDAFORTRAN_FUSED`（`cuda_dg_kernels_fused.cu`）だけ。
`FUSED_TC` / `FUSED_DFMA` は触っていない。

µs/stage = `CUDA device fused tendency` / (19 measured steps × 3 RK)。
採否は占有 GPU 上の 12 回交互 A/B。点変化係数の owned `dqdt`（`Ne=2³`）は
改修前 CC と**ビット一致**、`CUDAFORTRAN_SPLIT` との最大絶対差 1.78e-15。

### 5.1 判定基準の予測と、実際に起きたこと

`p15_gap_study.md` §27.3 の判定基準は「**(A) が効くのは shared wavefront で
詰まっている次数だけ**」で、§0 のとおり p=7 CC は
**L1/TEX 上の global ロード待ち（long scoreboard 45%）**なので**負け側**と
予測される。**予測は「shared 経路については」当たり、「時間については」外れた。**

p=7 CC は §2 の時点で既に **1 スレッド 2 出力**（`node1 = tid`,
`node2 = tid + 256`）で、共有できるオペランド（`mat_x`、`mat_y`、
`sFluxZ[iz]`）は 2 出力で割られている。512 ノードを 128 スレッドで覆って
**4 出力**にすると:

| メトリクス（ncu job `78031`） | 2 出力 / 256 thr | 4 出力 / 128 thr | 変化 |
|---|---:|---:|---:|
| shared wavefront | 54.30 M | 50.81 M | **−6.4%** |
| 発行命令 | 113.2 M | 88.18 M | **−22.1%** |
| global sector（LD） | 69.21 M | **69.21 M** | **0** |
| global request（LD） | 7.340 M | **7.340 M** | **0** |
| DRAM read / write | 1414 / 128 MB | 1409 / 129 MB | −0.4% / +0.8% |
| `long_scoreboard` | 7.79 | **2.705** | — |
| `barrier` | 4.995 | **0.890** | — |
| `mio_throttle` | 9.07 | 7.475 | — |
| `short_scoreboard` | 5.21 | 1.95 | — |
| L1/TEX | 95.3% | 92.8% | — |
| レジスタ / 実効占有率 | 40 / 72.4% | **96 / 30.2%** | — |
| ncu duration | 503 µs | 493 µs | −2.0% |

**shared wavefront はほとんど動かない（−6.4%。p=63 / p=127 は −38%）。**
判定基準が言うとおり、p=7 では (A) の shared 経路の賞金は無い。
動いたのは**命令数（−22.1%）とバリア**である: 面 flux の shared 書き込みと
`__syncthreads` が 1 スレッドあたり 4 出力に薄まり、リフト項の
`sLift[j]` / `sLift[i+8]` / `sLift[j+16]` / `sLift[i+24]` と面 5,6 の
`sflux_bnd` 読みが 4 出力で共有される（i, j はどの出力でも同じ）。
**global セクタとリクエストは 1 本も動いていない** —— §0 の律速そのものは
手つかずで、隠す側が良くなっただけである。

### 5.4 数値検証

### 5.5 現在地

**292.3 µs/stage** = **4.81 TFLOP/s（ピーク 40.1 の 12.0%）**、
unique DRAM **5.40 TB/s（7.9 の 68.3%）**。この次数はもともと DRAM の屋根に
最も近く、演算比が最も低い。

- 論文の主比 B は **TC / FUSED = 274.9 / 302.8 = 1.10× → 274.9 / 292.3 =
  1.06×**。最速は `FUSED_TC` のまま。
- §4 の 3 つの天井（P 側 gather −11.6%、内積 −13%、面 store のコンフリクト）は
  この改修で測り直していない。global セクタが 1 本も動いていないので、
  P 側 gather の天井はそのまま残っているはずである。

**判定基準（`p15_gap_study.md` §27.3）の 3 点目としての結論**:
「(A) は global 律速の次数には**移らない**」は **shared wavefront については
正しい**（p=7 −6.4%、p=15 −13〜22% に対し p=31 −35%、p=63 / p=127 −38%）。
しかし **時間については正しくない**: 出力タイルは shared だけでなく
**命令数とバリア**も出力で割るので、global 律速の次数でも
（p=15 −1.72%、p=7 −3.44% と小さいながら）勝つ。
判定基準は「(A) の**大きさ**は shared wavefront の詰まり方で決まる」と
読み替えるのが正しい。
