# 論文の Figure / Table 構成と、データの所在

- 日付: 2026-09-06、tree `90bef60`
- 目的: 載せる図表を確定し、**それぞれが既存データで描けるか、追加測定が要るか**
  を 1 行ずつ決める。measurement の抜けを図表側から潰すための一覧である。

物差しの規約（全図表共通）:

- **主軸は `Step loop per stage`**（`h100_report.md` §8.9.1）。`Main per step` は
  end-to-end の対照として補足に置く。**カーネル解析は `CUDA device` の
  µs/stage**。3 つを混ぜない。
- **屋根の分母は経路が発行する命令で決める**（`AGENTS.md`、`h100_report.md`
  §8.9.2）。CUDA core 経路は CC ピーク、`mma` / `DMMA` を出す経路は TC ピーク。
  GB200 は両者が同じ 40.1 TF、H100 は 33.5 / 66.9 TF、A100 は 9.7 / 19.5 TF。
- **演算強度は 2 本立て**: `I_alg`（アルゴリズム FLOP ÷ unique bytes）と
  `I_meas`（同 ÷ `ncu` 実測 DRAM bytes）。unique は実測の 0.98〜2.66 分の 1
  （`measured_dram_and_roofs.md` §2）。

## 3. 追加測定（2026-09-06、M1 / M2 とも完了）

- **M1: H100 の `roof_bytes_ncu`**（F3・T3 の H100 列）——**完了**
  （SGE `8585090`、14 起動とも `rc=0`）。`h100_report.md` §8.9.2 の唯一の
  未解明を閉じた: **H100 の volume GEMM は自分の DMMA 屋根の 88.1% で、
  絶対値では GB200 の 1.53 倍速い**。46.8% の正体は、演算をしない周辺
  カーネルが tendency の 41.0% を占めること（`measured_dram_and_roofs.md` §5.2）。
  **F3 / T3 は 2 台とも描ける。**
- **M2: H100 の反復増**（F1）——**p=31 は完了**（SGE `8585093`、10 ラウンド、
  9 経路とも 10/10 clean、MAD 0.01〜0.03%）。`stage` 軸は 6 ラウンドでも
  ±0.03% で再現し、動いたのは `Main` だけ（5.59%）で、**`16x8x4` は p=31 では
  無効（−0.11%）**と確定した。**p=511 / 575 / 767 も 8 ラウンドで完了**（SGE `8585186` / `8585211`、24 ラン `rc=0`）。
  **9 セルすべて 0.51% 以内で再現し、順位は不変、競合セルのレンジは非重複**——
  p=767 で cuBLAS が融合経路に 1.66% 勝つことも確定した（`h100_report.md` §8.10.3）。
  比の表は 1.230 / 1.201 / 1.111 で 3 桁目しか動かない。**M2 は完了。**


## 4. 載せないと決めたもの

- **H200 / GH200 での帯域介入実験**。「mma は命令律速を外して帯域に移す」の
  直接検証にはなるが、アクセスが無い。**3 台目は A100 で既にあり**、
  TC 屋根が CC の 2 倍ある低帯域機という点をカバーしている
  （`a100_report.md`）。追加できるなら価値は高い、という記述に留める。
- **multi-GPU / 電力**。単 GPU の性能モデルの論文なので範囲外。
- **実アプリ（SCALE-DG 本体）での確認**。本リポジトリは抽出であり、
  本体側の作業になる。数値契約は抽出インタフェースに対して定義されている。
