### 2.2 現在使われている 3 種類の物差し

`p63_gap_study.md` §52.5 が区別しているもの:

1. **`CUDA device *` ÷ stage 数** —— テンダンシーだけの device 時間。
   現在の公表表の標準。stage 数は `3 × (nstep − WarmupStep)`。
2. **`Step loop per stage`** —— 1 step 全体（halo + tendency + RK 更新）を
   device 同期境界で測って ÷ (3·steps)。水準は 1 より高い。
3. **`Cal_tend`** —— 非同期 enqueue のホスト側。区間外の RK 更新を抱え、
   最後の stage の drain を取りこぼす。

`p767_gap_study.md` §15 が定量化した偏り: `Cal_tend` 系はちょうど 1 stage 分
少なく（33 stage で −3.0%、75 stage で −1.3%）、CUDA イベント系は 1 stage 分
多く数える。**正しい割り方は `Cal_tend` ÷(3·steps−1)、`CUDA device *` ÷(3·steps+1)**
だが、**タイマ本体は直さないと 2026-09-01 に判断された**ため、公表表の多くは
÷(3·steps) のままである。

## 5. 既定ノブが改修前と同形かの確認

`3d4045c` 以降のノブを全部洗った（`getenv` / `get_environment_variable` を
`*.cu` / `*.cuf` / `*.h` / `*.f90` で grep）。

| ノブ | 既定 | 既定は改修前と同形か |
|---|---|---|
| `SCALE_DG_XCUTLASS` / `XTILE` / `YCUBLAS` / `ZCUBLAS` / `CARRIER` / `XFWD` / `XPKG` / `ZPKG` / `ZTILE` / `YSCHED` | `-1`（次数別テーブル `dg_gemm_defaults`） | ○ 未設定なら環境を一切読まず、テーブル駆動の採用構成そのもの |
| `SCALE_DG_ZSKIP` / `CSKIP` / `FSKIP` / `VSKIP` | `0` | ○ アブレーション専用、既定は正規経路 |
| `SCALE_DG_VARYING_COEFF` | `0` | ○ 検証専用 |
| `SCALE_DG_REPORT_DEVICE_MEMORY` / `DUMP_Q` / `DUMP_DQDT` / `OZAKI1_SLICE_STATS` / `OZAKI1_VERBOSE` / `OZAKI2_CHECK` | オフ | ○ 診断専用 |
| **`SCALE_DG_FLUXFUSE`** | **`1`（融合）** | **× 既定が新挙動**。コード中コメントが「0 = 分離（**2026-09-03 より前のすべての測定が使っていた形**）」と明記 |
| **`SCALE_DG_GVOLPAR`** | **`2`（3 本並列）** | **× 既定が新挙動**。mode 1 で −1.23〜−2.82% とコメント |

**これは defect ではなく意図した採用である。** `3d4045c` は両者を測って採用した
コミットで、`gemm_assignment_and_carrier.md` §9.1 / §9.4 が A/B を記録している。
ただし **「既定が改修前と同形」ではない**ので、`3d4045c` より前の GEMM 系の
値と現行値を同じ表に並べてはならない。本棚卸しの (c) はこの 2 ノブが起点である。

なお `941b066` は、**既定 `SCALE_DG_GVOLPAR=2` × `CublasEmulation=.true.` の
組み合わせで owned `dqdt` に ±Inf が出る**という数値バグの修正で、
`3d4045c` が入れた既定変更の副作用だった（cuBLAS emulation はハンドルと
8 GiB workspace を 1 つしか持たないため）。`gemm_assignment_and_carrier.md`
§9.5 の性能表は明示的に `SCALE_DG_GVOLPAR=0` で採っているので汚染されていない。
